Machine Learning · Classification

Iris Flower Classification

Objective: classify iris flowers into three species – Setosa Versicolor Virginica – using the measurements of their sepals and petals.

Every number and chart on this page is computed by real scikit-learn code (export_data.py) on the real dataset – nothing is hardcoded.

The problem in plain words

Imagine you find an iris flower and want to know its species. A botanist would measure it: how long and wide are the sepals (the outer green leaves of the bud) and the petals (the coloured part)? Our goal is to teach a computer to do the same: given 4 numbers, predict 1 of 3 species.

This is called supervised classification: we show the computer many flowers whose species we already know (training data), it learns the pattern, and then we test it on flowers it has never seen (test data).

Step 1

Load the dataset

We use the classic Iris dataset, bundled with scikit-learn (load_iris(); also available from the UCI Repository). The measurements were collected by the botanist Edgar Anderson and made famous by the statistician R.A. Fisher in his 1936 paper.

What is in it?

  • flowers – exactly 50 of each species (a balanced dataset).
  • 4 features (inputs), all in centimetres: sepal length, sepal width, petal length, petal width.
  • 1 target (output): the species – Setosa, Versicolor or Virginica.
  • No missing values, so the data is already clean.
  • rows are exact duplicates of another row (computed, and harmless here).

Step 3

Split into training and test sets

If we tested the model on the same flowers it learned from, it could just memorise them and we would learn nothing about how it handles new flowers. So we hide part of the data:

  • Training set (80%) – the model learns from these flowers.
  • Test set (20%) – kept locked away until the end, used only to measure performance.

We use a stratified split (stratify=y), which keeps the species balanced in both sets, and a fixed random seed () so anyone can reproduce the same split.

Step 4

Preprocess the data

The Iris data is already clean: no missing values, no text columns, no obvious errors. The only thing we do is feature scaling with StandardScaler: each feature is shifted and stretched to have mean 0 and standard deviation 1:

z = (x − mean) ÷ standard deviation

Why? Models like KNN measure distances between flowers and Logistic Regression is trained by gradient-based optimisation, so features on different scales can distort them. (Decision Trees don't need scaling, but it does no harm.)

Avoiding data leakage: the scaler is fitted on the training set only, then applied to the test set. If we fitted it on all the data, information from the test flowers would secretly leak into training and make the results look better than they really are.

Step 6

Evaluate the results

Now we unlock the test set and ask each model to classify flowers it has never seen. We compare its predictions with the true species using these metrics:

Accuracy

Share of all predictions that were correct.

correct ÷ total

Precision

Of the flowers predicted as a species, how many really were that species?

TP ÷ (TP + FP)

Recall

Of the flowers that truly are a species, how many did we find?

TP ÷ (TP + FN)

F1-score

One number balancing precision and recall (their harmonic mean).

2·P·R ÷ (P + R)

With 3 classes, precision/recall/F1 are computed per species and then macro-averaged (simple average of the three).

Test-set scores

Confusion matrices

Rows = the true species, columns = what the model predicted. Numbers on the diagonal are correct predictions; anything off the diagonal is a mistake.

Can we trust a single test score?

The test set has only flowers, so one mistake changes accuracy by about 3.3 points. To get a steadier estimate we also run 5-fold stratified cross-validation on all 150 flowers: the data is split 5 ways, and every part takes a turn as the test set. We report the mean ± standard deviation.

Be honest about Iris: it is a small (150 flowers), clean, well-separated dataset, so very high scores are normal and expected. Differences between models of a point or two are within the noise. These scores do not mean the same models would be this accurate on harder real-world problems.

Conclusion

Skills gained

📊 Numeric data analysis

Loading data with pandas, summary statistics, histograms, scatter plots, correlation and ANOVA.

🤖 Classification modelling

Splitting data, scaling features without leakage, and training Logistic Regression, KNN and Decision Tree.

✅ Evaluating results

Accuracy, precision, recall, F1, confusion matrices and cross-validation – and knowing their limits.

Limitations

  • Only 150 samples and 30 test flowers – scores are noisy.
  • Iris is easy; real data is messier (missing values, imbalance, noise).
  • Models only know these 3 species: a rose or tulip would still be forced into one of them.
  • The out-of-range warning is a simple range check, not a full anomaly detector.
